# 1.2.9：保留尚未验证的大图候选

多张图片异步加载时，较慢图片可能一直显示缩略图尺寸。例如网页将缩略图显示为300×400，缩略图文件实际为600×800，原图为1800×2400。缩略图先加载完成，其他图片的尺寸更新随后触发列表刷新，较慢的原图即使已经开始请求，最终也可能没有更新到卡片。

原因是后台把“缩略图比网页显示尺寸大”误判为“原地址已经比高清候选大”，提前用缩略图地址替换了未验证的高清候选。刷新后探测任务的来源发生变化，旧任务的较大结果被丢弃，新的任务则只知道缩略图。

现在仅在现有高清地址已经测量验证、且原地址确实更大时，才允许原地址替换它。工作台和弹窗同时完成两张图的比较时，也会把比较过的候选地址带回后台；即使缩略图尺寸此前已经保存，也能正确选择较大的原地址。比较结果不能覆盖后来换入的其他候选或更新的更大尺寸。单独更新缩略图的实际尺寸不会取消仍未验证的候选，加载失败的候选仍可重试。

这一修改位于通用图片状态管理，不依赖网站域名、图片编号、分页结构或页面标题。

同时修正了较小预览迟到时的元数据上报：图片地址始终携带该图片的实测尺寸，不再与另一张图片的已存最大尺寸混用。后台保留已确认的较大地址。

## 验证

- 状态回归：先测量600×800缩略图时保留未验证候选，随后接受1800×2400原图。
- 反例保护：原地址确实大于已经验证的低分辨率回退图时，仍选择更大的原地址。
- 同时比较：工作台与弹窗首次同时测量原地址和较小高清候选时，保存较大的原地址；覆盖缩略图已提前测量和未提前测量两种时序。
- 旧记录恢复：重新扫描可以恢复以前被缩略图覆盖、尚未验证的大图候选。
- 完整扩展回归：两个通用背景缩略图，一张大图先完成并触发列表刷新，另一张大图由测试服务器暂缓返回。旧版本会覆盖候选并失败，修复版保留候选，延迟响应释放后正确更新尺寸和大图地址。
- 完整消息链：同一脚本还验证工作台和弹窗经真实后台消息入口保存600×800原地址，且400×500候选的迟到预览不再改回小图。弹窗页面在测试中显式绑定来源标签页。
- 测试使用本地服务器和生成的纯色图片，不包含网站特判或用户原始图片。运行：`node scripts/browser-image-candidate-race.mjs`，浏览器配置方式与其他浏览器回归脚本一致。
- 本轮263项Node测试、56个JS/MJS语法检查及原有20项完整扩展浏览器场景通过；用户提供的原案例另行在独立浏览器配置中验证为1800×2400。

加载目录不变。重新加载后，扩展版本和显示版本均为1.2.9；已有结果建议关闭旧工作台、重新打开并扫描，以更新先前保存的候选信息。

## Pro 复核后的重试修正

复核确认主体竞态修复有效，并指出两条尚未覆盖的路径，现已补齐：

- WebP 候选临时失败、较小 JPG 备用图成功时，只把测量证据记在实际成功的 URL 上，不把备用图当作原候选已完成比较的证明。原候选仍保留有限重试期限。
- 弹窗在同格式高清图恢复后，也会保存更大的实测尺寸或新增的候选验证状态；不再要求格式先发生变化。复用已经完成的缓存不会再次写回，格式没有变化时也不额外刷新格式筛选。

新增两个经实际后台消息分支的失败回归先红后绿，并补充同尺寸候选首次验证与已验证不重复发送的正反例。完整扩展脚本现有五个场景，新增工作台与弹窗的失败后恢复：测试实际等待30秒冷却期，然后确认重新请求原候选、后台由600×800更新为1800×2400，格式保持不变。浏览器请求来自本地生成图片，未模拟时间或清空探测缓存来绕过重试期限。

## 较大备用图接管后的原候选重试

后续复核发现，备用 JPG 如果大于缩略图，当前可用地址会正确升级为 JPG，但到期后探测目标也随之改变，失败 WebP 不再被请求。现在尺寸缓存分别保留当前最佳结果与待重试地址；重新读取后台记录后，仍会把待重试地址加入探测。实测成功后才移出重试列表，集合或来源改变时不沿用旧列表。

新增600×800缩略图、1200×1600 JPG、先失败后恢复为1800×2400 WebP的失败回归，验证等待期间保留可用JPG，成功后更新原候选地址和后台尺寸。新增刷新未到期不重复探测、成功后停止重试的断言。完整扩展脚本现有六个场景，较大备用图场景同样经过真实冷却时间，并用服务端请求次数确认原WebP确实被重新请求。

## 预览先完成时接管在途探测

如果全屏 JPG 预览先完成，卡片的原 WebP 探测可能仍在等待，此时尚未生成失败重试列表。现在任务创建时就记录其负责的地址、来源和会话；同一来源和会话中的刷新会把在途目标交给新任务。URL 探测队列继续复用同一网络请求，原任务身份及会话检查保留。

新增迟到成功、迟到失败后恢复两个先红后绿回归，以及同一图片 ID 更换来源时不继承旧探测的反例。完整扩展脚本现有八个场景，新增通过真实卡片点击、全屏预加载及原生图片 onload 触发 JPG 地址更新，再刷新列表并释放原请求；成功结果正确写回，失败结果在真实冷却后重新请求。没有直接调用全屏 onload 或伪造自然尺寸。标签页承载的 Popup 测试会等待初始化结束后再绑定来源，避免测试自身的初始化竞态。
